## What was changed for lazy allocation

1. `sys_sbrk` reserves the valid virtual address range when growing the heap instead of immediately calling the eager allocator. Shrinking still releases pages through the existing growth/shrink path.
2. New `kernel/pgfault.c` validates the address, allocates and zeroes one physical page, and maps it into the process. Invalid/protection faults and allocation failures return an error.
3. `usertrap` routes load/store page faults to this handler, allowing a valid faulting instruction to retry after its page is supplied.
4. `uvmunmap` and `uvmcopy` skip missing mappings so untouched pages do not cause panics during cleanup or fork.
5. A shared `pin_user_page` helper and replacement `copyout`, `copyin`, and `copyinstr` resolve missing mappings for system-call buffer access. Successful physical-memory accesses are paired with `pop_off()`.
6. Build declarations/object entries and the `baseline` and `lazytest` user programs support integration and demonstration.
